## [llama.cpp b11000 修复 RPC 服务器远程代码执行漏洞](https://github.com/ggml-org/llama.cpp/releases/tag/b11000) ⭐️ 8.0/10

llama.cpp 的 b11000 版本修复了其 RPC 服务器中的一个释放后使用（use-after-free）漏洞（PR #24292），该漏洞可被未认证的远程客户端触发。补丁在 free_buffer() 中丢弃所有缓存的 compute graph，使得 graph_recompute() 中已有的空指针检查会拒绝该请求，客户端随后回退到 GRAPH_COMPUTE。 由于该漏洞无需认证即可被远程利用，并可能导致远程代码执行，任何在网络或多租户环境中运行 llama.cpp RPC 服务器的用户都应立即升级。这也凸显了通过网络暴露后端设备的分布式 LLM 推理工具日益扩大的安全攻击面。 服务器原本会按设备缓存最近的 compute graph，以便 GRAPH_RECOMPUTE 无需重新发送张量数据即可重新执行，但缓存的图节点持有指向后端缓冲区的直接指针，而这些缓冲区之后可能通过 FREE_BUFFER 被释放。攻击者可以利用后续的 ALLOC_BUFFER/SET_TENSOR 命令重塑这些悬空内存块，从而泄露 libc 地址并劫持 BUFFER_CLEAR 使用的 buffer iface vtable；该修复不涉及任何协议或 API 变更。

github · github-actions[bot] · Sep 16, 13:07

**背景**: llama.cpp 是一个被广泛使用的开源 C/C++ 大语言模型推理引擎，其 ggml-rpc-server 组件允许一台机器将自身的 ggml 设备暴露给远程主机，从而将计算卸载出去以实现分布式推理。释放后使用（use-after-free）是指内存被释放后仍被引用，使攻击者能够通过悬空指针控制读取或写入的内容。在本例中，RPC 服务器的图缓存恰好制造了这种条件，而由于服务器接受未认证连接，任何远程客户端都能触达该漏洞。
