Cloudflare 发布了一篇博客文章，详细介绍了其大规模服务 Kimi 和 GLM 模型的方式，重点强调了使用 KV 缓存量化来提高效率和安全性，同时承认可能存在质量权衡。 这很重要，因为它展示了一家主要基础设施提供商优化 LLM 服务的方法，这可能影响使用这些模型的开发者的成本、延迟和安全性。同时，它为 AI 服务领域中常见但往往不透明的做法增加了透明度。 该文章特别讨论了 KV 缓存量化，这是一种通过以较低位格式（如 FP8 或 INT4）存储注意力键和值来减少内存使用的技术。Cloudflare 指出，在某些情况下，这比权重量化更能降低质量，并且他们只测试了 Kimi K2.6 模型系列，这给其他模型留下了疑问。

## [AirLLM 在单张 4GB GPU 上运行 70B 大语言模型](https://github.com/lyogavin/airllm) ⭐️ 8.0/10

开源项目 AirLLM 使得在单张 4GB GPU 上无需量化、蒸馏或剪枝即可推理 70B 参数的大语言模型。这是通过创新的内存优化技术大幅降低内存占用实现的。 这一突破降低了运行大型语言模型的硬件门槛，使拥有有限 GPU 资源的个人和小型组织也能使用。它可能使先进 AI 能力更加普及，并推动内存高效推理领域的进一步创新。 模型参数存储在磁盘上，推理时逐层加载到 GPU 内存中，因此仅需 4GB 显存即可运行。然而，这种方法导致推理速度非常慢；例如，在 RTX 6000 Ada（48GB）上运行 Kimi K3 每个 token 需要 292 秒。

hackernews · Anon84 · Aug 3, 11:15 · [社区讨论](https://news.ycombinator.com/item?id=49154228)

**背景**: 像 70B 参数这样的大型语言模型通常需要巨大的 GPU 内存（例如 70B 模型需要 130GB），往往需要多块高端 GPU。传统的降低内存使用的方法包括量化、蒸馏或剪枝，但这些可能会降低模型质量。AirLLM 则采用逐层加载和高效内存管理等内存优化技术，避免了质量损失。

## [Cisco FMC 严重认证绕过漏洞可导致根权限获取](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-onprem-fmc-authbypass-5JPp45V2?vs_f=Cisco%20Security%20Advisory%26vs_cat=Security%20Intelligence%26vs_type=RSS%26vs_p=Cisco%20Secure%20Firewall%20Management%20Center%20Software%20Authentication%20Bypass%20Vulnerability%26vs_k=1) ⭐️ 8.0/10

Cisco 披露了 CVE-2026-20079，这是 Secure Firewall Management Center (FMC) 软件 Web 界面中的一个严重漏洞，允许未经身份验证的远程攻击者绕过身份验证并执行脚本，从而获得底层操作系统的 root 权限。目前已有软件更新，但没有变通方案。 该漏洞至关重要，因为 FMC 是广泛使用的企业防火墙管理平台，成功利用可授予完全 root 权限，可能危及整个防火墙基础设施。由于没有变通方案，受影响组织急需应用更新。 该漏洞源于启动时创建的系统进程不当，利用方式涉及向受影响设备发送特制的 HTTP 请求。如果 FMC 管理接口不公开访问，攻击面会减小，但风险仍然很高。

rss · Cisco Security Advisories · Aug 3, 17:27

**背景**: Cisco Secure Firewall Management Center (FMC) 是 Cisco 防火墙的集中管理平台，提供配置、监控和策略管理。认证绕过漏洞非常关键，因为它们允许攻击者在没有凭据的情况下获得未授权访问，通常导致系统完全受损。Cisco 定期发布安全公告，作为 ASA、FMC 和 FTD 软件半年一次捆绑发布的一部分。
