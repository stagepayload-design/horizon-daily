## [Deno 发布 Celld：自托管分布式持久对象](https://github.com/denoland/celld) ⭐️ 8.0/10

Deno 宣布了 Celld，一个自托管的分布式持久对象运行时，它将基于 SQLite 的对象复制到兼容 S3 的存储中，实现与提供商无关的持久状态。它利用对象存储的比较并交换（CAS）机制，确保在任何时刻只有一个节点拥有一个单元，无需成员协议、故障检测器或共识服务。 Celld 通过提供自托管的持久对象替代方案（如 Cloudflare 的持久对象），填补了生态系统中的一个重要空白，赋予开发者更多的控制权和灵活性。这可能加速持久对象抽象在去中心化和边缘计算环境中的采用。 Celld 持续将每个单元的 SQLite 数据库复制到存储桶中，当单元移动或唤醒时，其新所有者会恢复数据库并继续执行。该项目在 GitHub 上开源，但禁用了拉取请求，贡献需通过 git format-patch 提交。

hackernews · calvinfo · Aug 5, 16:50 · [社区讨论](https://news.ycombinator.com/item?id=49185430)

**背景**: 持久对象是一种编程抽象，其中每个对象拥有自己的持久状态，通常由数据库支持，并可通过名称寻址。Cloudflare 的 Durable Objects 推广了这一概念，使用 SQLite 进行存储，但它们与 Cloudflare 平台绑定。Celld 旨在提供类似的抽象，但可以自托管，利用兼容 S3 的存储进行复制和所有权管理。

## [思科 FMC 静态凭据漏洞允许未认证访问](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-fmc-static-cred-BET3Cjh?vs_f=Cisco%20Security%20Advisory%26vs_cat=Security%20Intelligence%26vs_type=RSS%26vs_p=Cisco%20Secure%20Firewall%20Management%20Center%20Software%20Static%20Credential%20Vulnerability%26vs_k=1) ⭐️ 8.0/10
